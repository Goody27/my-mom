## 意図分析

| 項目 | 内容 |
|------|------|
| プロダクト名 | MyMom（マイマム） |
| チーム名 | 音部に抱っこ |
| リクエスト種別 | 新規プロダクト（グリーンフィールド） |
| スコープ | MVP: Slack DM、将来: LINE/メール/Discord |

---

## プロダクトコンセプト

> **「人をダメにするシステム」**
> 使えば使うほど思考しなくなる、信頼委任設計。

AIが「お母さん」として先回りして意思決定・行動を代行し、**失敗の責任を一緒に引き受ける**プッシュ型サービス。

ユーザーは選択肢を提示されるのではなく、**もう判断が終わっている**。MyMomはその委任を極限まで快適にする。

### アイデアの抽象化プロセス

```
「言葉を代わりに選んでくれるAI」（恋愛地雷分析）
        ↓
「全判断代行AI（AIがすべての意思決定をする）」
        ↓
「お母さん（先回りして失敗をゼロにする）」← 最終形
```

### 他のLLMツールとの本質的差異

| 観点 | 既存LLM/エージェント | **MyMom** |
|------|---------------------|-----------|
| 動作タイミング | ユーザーが指示した時 | **先回りして既に動いている** |
| 判断主体 | ユーザーが選択肢を選ぶ | **MyMomが判断している** |
| 責任の所在 | ユーザーが意思決定した | **MyMomが責任を引き受ける** |
| キャラクター | なし | **「お母さん」として感情的接続が生まれる** |
| 差別化の一言 | 選択肢を提示してくれる | **もう断った。あなたは何もしていない** |

## 勝ち戦略（ハッカソン）

技術的な完成度より**思想・コンセプト・将来性**で勝負する。
審査員への訴求軸は「このプロダクトの考え方が面白い＋実際に動く最小限のMVP」。

- 去年の優勝チームは設計思想のプレゼンで差別化した実績あり
- 10日間で完璧なプロダクトは不可能。コンセプトと整合したMVPを見せ、「今後はLINE/メールにも拡張」を語る
- デモはチームのSlack workspaceで実演（外部公開・審査員への開放は不要）

---

## MVP スコープ（Slack選定理由）

**なぜSlackか：**
- Slack Bot APIが最も実装コストが低く、即座にデモ可能
- ボタン・インタラクティブコンポーネントが標準装備でUX表現が豊か
- チームメンバーが普段使っており、デモシナリオがリアル
- LINE APIはリード権限など制約が多くMVPには向かない

**MVP対象：**
- Slack DM の自動断り代行
- Slack上でお母さんとチャット（Bedrock Agent直接会話）

**将来展開（プレゼン内で語る）：**
- LINE・メール・Discord対応
- バーチャルお母さん UI（顔・音声）
- 全ツールを束ねるアプリ（一元管理フロント）

---

## お母さんメーター（信頼委任の段階）

```
信頼度 0〜40%  : お母さんが案を作り、ユーザーが最終確認して送信
信頼度 40〜79% : 送信するけど3秒の取り消しウィンドウあり（通知あり）
信頼度 80%以上 : もう断った。ユーザーは「断っておいたよ」通知だけ受け取る
```

信頼度はMyMomがユーザーの反応・フィードバック・承認率から自動更新。
使えば使うほどお母さんに任せるのが当たり前になる。

## 機能要件

### FR-01: Slack断り代行（MVP・デモコア）

**シナリオ**: 「今週末出社お願いできますか？」とSlackにDMが届く

| ステップ | 処理 |
|---------|------|
| 1 | EventBridge 1分ポーリングでDMを取得 |
| 2 | Bedrock Agentがユーザーの直近コンテキスト・パーソナリティを分析 |
| 3 | Bedrock Guardrailsが倫理審査（ハラスメント・違法コンテンツをブロック） |
| 4 | 「断るべき」と判断し、角が立たない断り文を生成 |
| 5 | **ユーザーの承認なしに**Slackで自動返信（信頼度80%以上の場合） |
| 6 | ユーザーへの通知は「断っておいたよ」のみ |

### FR-02: Slackチャット（Bedrock Agent直接会話）

- SlackのMyMom DM上でユーザーがお母さんと会話できる
- `/slack/chat` エンドポイント経由でBedrock Agentを呼び出し
- セッションID = `chat-{userId}` で会話履歴を保持（Agent session）
- 処理中は「お母さん考えてるよ…ちょっと待ってね🤔」を先送り

### FR-03: 倫理フィルタ

- Bedrock Guardrailsをエージェントに直接アタッチ
- ブロック対象: ハラスメント・違法リクエスト・プライバシー侵害
- ブロック時: SNS経由でエスカレーション、自動送信しない

### FR-04: おせっかいプッシュ型通知（将来）

お母さんが自発的に動く「おせっかい」機能。ユーザーが何もしていなくても：
- 「最近気になってる人いる？」と定期的に聞いてくる
- ユーザーが「いる」と答えたら3日後にそっとDMを送っておく
- 「ちょっと部屋が散らかってない？」など日常の気遣い通知

> お母さんらしさの核：最低限のラインは超えないが、おせっかいでプッシュしてくる

### FR-05: AIパーソナリティ分析・プロファイル公開

- 判断ログ・チャット履歴・委任パターンを週次で分析（EventBridge週次cron）
- 4スコアを算出: `断り苦手度` `先延ばし傾向` `完璧主義度` `承認欲求度`
- パーソナリティプロファイルをBedrock system promptに注入 → 判断精度向上
- 公開カードとして生成（オプトイン制）、Twitter Card対応でバイラル設計

### FR-06: 責任SLA

- MyMomの判断が誤りで失敗が発生した場合、MyMomが謝罪文を生成して送信
- ユーザーには「対処しておいたよ」通知のみ

### FR-07: オンボーディング・同意設計

初回起動時に以下を明示確認:
- 「お母さんがあなたの代わりに行動します。実行前に3秒の取り消しウィンドウがあります」
- 「いつでも自動実行をOFFにできます（設定 > お母さんモード）」

**第0段階：Ahaモーメント設計（インストール後15分）**

```
1. Slack Appインストール完了
   ↓
2. MyMomから1通目のメッセージ:
   「はじめまして。お母さんだよ。最近断れなかった予定、ある？今すぐ練習しよ。」
   ↓
3. ユーザーが状況を入力（任意）:
   例:「来週の歓迎会、行きたくないけど断れてない」
   ↓
4. MyMomがその場で断り文を生成・提示（送信するかはユーザーが決める）:
   「断り文つくったよ。送ってみる？それとも自分でアレンジする？」
   ↓
5. 「こういうことを、次からは自動でやっといてあげる」
```

### FR-08: 高依存ユーザーへの自律回復設計

- 依存度スコアが「超高」（80超）を14日間継続した場合:
  > 「最近お母さんに頼りすぎじゃない？たまには自分でやってみて。応援してるよ。」
- メンタルヘルスに関わる判断は常に人間エスカレーション

## 非機能要件

### NFR-01: レイテンシ

| 処理 | 目標 |
|------|------|
| DM検知〜断り文送信（エンドツーエンド） | ≤ 90秒（EventBridge 60秒 + Bedrock 30秒） |
| Bedrock Agent応答 | ≤ 30秒（Lambda timeout: 60秒） |
| 取り消しウィンドウ | 3秒（SQS DelaySeconds=3） |
| チャットAPI応答 | ≤ 10秒（p99、Bedrock Agent含む） |

### NFR-02: 可用性

| 要件 | 実装 |
|------|------|
| 目標SLO | 99.9% |
| SQS DLQ | maxReceiveCount=3、失敗メッセージをDLQで保全 |
| Lambda | 指数バックオフで2回リトライ |
| DynamoDB べき等性 | requestIdはUUID、PENDING→CANCELLED状態フラグで排他制御 |

### NFR-03: セキュリティ

| 要件 | 実装 |
|------|------|
| シークレット | AWS Secrets Manager必須（ハードコード禁止） |
| Slack Webhook認証 | X-Slack-SignatureのHMAC-SHA256検証（全リクエスト必須） |
| リプレイ攻撃防止 | タイムスタンプ±5分超は即座に403 |
| IAM | Lambda関数ごとに専用ロール・最小権限 |

### NFR-04: コスト

**MVP期間（ハッカソン）**: < $10/月（Bedrock Agent呼び出し含む）

### NFR-05: データプライバシー

| 項目 | 方針 |
|------|------|
| 判断ログ保持期間 | 90日間（DynamoDB TTL） |
| 解約後データ削除 | 解約後30日で完全削除 |
| パーソナリティカード共有 | デフォルトOFF・オプトイン制 |
| 第三者メッセージの扱い | 判断目的のみ利用、外部送信・学習に使用しない |

### NFR-06: 倫理・ユーザー保護

- 第三者への配慮: 断り文末尾にAIフッター付記
  > `（このメッセージはAIアシスタント MyMom により生成されました）`
- メンタルヘルスに関わる判断は人間エスカレーション必須
- 依存度スコア80超・14日継続でブレーカー発動

## 信頼委任の段階

```
第0段階（インストール後15分以内）: 「これ、本当に動いた」← Ahaモーメント
第1段階（0〜1週間）: 「便利だな」← 時間・精神コストの削減を体感
第2段階（1〜4週間）: 「MyMomが見てるからいい」← 自己確認行動が自然と減る
第3段階（3ヶ月〜）: 「MyMomなしで何をすればいいか分からない」← 実存的委任
```
