# ロードマップ — MyMom

## ロードマップの考え方

MVP（Slack断り代行）を起点に、「お母さんに任せる範囲」を段階的に拡張する。
技術的な難易度より**ユーザーの信頼委任が自然に深まる順序**で展開する。

---

## Phase 0 — MVP（ハッカソン提出、2026年6月）

**目的**: 「これ、本当に動いた」を審査員に届ける

| 機能 | 内容 |
|------|------|
| Slack断り代行 | DM検知 → Bedrock Agent判断 → 自動返信 |
| お母さんメーター | 信頼度0〜40% / 40〜79% / 80%+ の3段階自律制御 |
| Slackチャット | Slack DM上でBedrock Agentと直接会話（セッション継続） |
| パーソナリティカード | 4スコア生成・SNS共有（オプトイン） |
| 責任SLA | MyMomのミスはMyMomが謝罪文を生成・送信 |

**制約**: チームのSlack workspaceのみ対応。外部公開なし。

---

## Phase 1 — プラットフォーム拡張（ハッカソン後 〜3ヶ月）

**目的**: Slack以外のコミュニケーションチャネルへの拡張

### P1-1: LINE連携

LINEは通知機能しか提供できないため、「自社チャット画面 + LINEに通知を送る」構成で実現する。

```
ユーザー ─── 自社チャット画面 ─── MyMomバックエンド
                                        │
                              LINE Messaging API
                                        │
                              LINEで「断っておいたよ」通知
```

| タスク | 内容 |
|-------|------|
| 自社チャットUI | React/Next.js製のチャット画面（Slack依存を排除） |
| LINE Messaging API | Webhookでメッセージ受信・送信 |
| 通知ブリッジ | MyMomの行動結果をLINEプッシュ通知に変換 |

### P1-2: メール対応

- Gmail / Outlook から断りが必要なメールを検知
- 返信文をBedrock Agentが生成し、ユーザー確認後に送信

### P1-3: おせっかいプッシュ通知（FR-04実装）

ユーザーが要求していないのに、状況を察知して行動を起こす。

| おせっかいの種類 | トリガー | アクション |
|----------------|---------|----------|
| 人間関係気遣い | 週1回定期 | 「最近気になってる人いる？」→ 3日後にそっとDM |
| 日常気遣い | 行動パターン分析 | 「ちょっと部屋が散らかってない？」 |
| 愚痴モード | ユーザーの愚痴を検知 | 傾聴 → パーソナリティプロファイルへ反映 |

---

## Phase 2 — パーソナリティ深化（3〜6ヶ月）

**目的**: お母さんがユーザーを「知り尽くす」段階

### P2-1: バーチャルお母さんUI

| 要素 | 内容 |
|-----|------|
| アバター | お母さんの顔（イラスト・選択式） |
| 音声 | Text-to-Speech でお母さんが話しかけてくる |
| 感情表現 | 「心配してるよ」「よかったね」をアバターで表現 |

### P2-2: 依存度ブレーカー（FR-08）

```
依存度スコア > 80 かつ 14日継続
  → 「最近お母さんに頼りすぎじゃない？たまには自分でやってみて。応援してるよ。」
```

メンタルヘルスに関わる判断は常に人間エスカレーション。

### P2-3: パーソナリティカードのバイラル強化

- Twitter Card OGP 対応（Phase 0 では基本実装のみ）
- 「友人のカードと比較」機能でシェアのインセンティブ追加
- 紹介コード → 友人インストール導線

---

## Phase 3 — ライフイベント対応（6ヶ月〜）

**目的**: 日常の断り代行を超えて「人生の節目」でも頼られるお母さんへ

| ライフイベント | MyMomの対応 |
|-------------|-----------|
| 転職 | 入社手続き・保険切り替え・住民票変更のリスト化と順次実行 |
| 引越し | 電気ガス水道の手続き・転居届の自動リマインド |
| 結婚・離婚 | 各種名義変更・手続きの代行 |
| 育休・復職 | 職場への連絡文・申請書類の生成支援 |

```
ライフイベント検知（メール・カレンダー）
  → 「転職版お母さん」へのバージョンアップを提案
  → 手続きリストを自動生成 → 順番に実行
```

---

## Phase 4 — 一元管理プラットフォーム（1年〜）

**目的**: 全コミュニケーションツールをMyMomが横断管理

```
┌─────────────────────────────────┐
│        MyMom ダッシュボード       │
│  （一元管理フロント）             │
└──────┬──────┬──────┬────────────┘
       │      │      │
    Slack   LINE   メール  Discord ...
```

- ユーザーはMyMomのダッシュボードだけ見ればよい
- 各チャネルへの返信はMyMomが自動ルーティング
- 「このチャネルには返信率100%、このチャネルは5%」のような分析を提供

## 技術的マイルストーン

| フェーズ | 主要技術追加 |
|---------|------------|
| Phase 0 | Bedrock Agent + Slack Bot API + SQS + DynamoDB |
| Phase 1 | LINE Messaging API + 自社チャットUI（Next.js）+ EventBridge cron |
| Phase 2 | Amazon Polly（音声）+ S3（アバター画像）+ CloudFront（CDN） |
| Phase 3 | Gmail API / Outlook API + Amazon Textract（書類読み取り） |
| Phase 4 | AppSync（リアルタイム同期）+ マルチテナント設計 |
