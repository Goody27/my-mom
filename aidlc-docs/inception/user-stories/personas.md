# Personas — MyMom

## 1. Purpose

このドキュメントは、MyMomのInceptionフェーズにおけるUser Story Creationの前提資料である。

目的は、`requirements.md` と `requirement-verification-questions.md` で定義したプロダクト方針を、具体的なユーザー像と心理構造に落とし込むことである。

MyMomの核は、ユーザーが本当は少し気になっているが、自分から動くほどではない行動に対して、**「自分から始めたわけではない」と言える状況**を作ることである。

MyMomが対象にするユーザーは、何もしたくない人ではない。
むしろ、本当は少し気になっていることがある人である。

ただし、その興味はまだ弱い。

* 自分から動くほどではない
* 自分が興味を持っていると認めるのが少し恥ずかしい
* 誘う、探す、予約する、予定化するのが面倒
* 失敗しても自分の選択だったと思いたくない
* 誰かに押されたことにできれば動ける
* MyMomを言い訳の対象にできると行動しやすい

このペルソナ定義は、後続の `stories.md` において、ユーザー心理と言い訳成立の構造をUser Storiesへ変換するための入力となる。

## 2. Primary Persona

## P1: 弱い興味を行動化できない20代社会人

### 2.1 Profile

| Item             | Description                            |
| ---------------- | -------------------------------------- |
| Name             | Haru                                   |
| Age              | 25                                     |
| Occupation       | 会社員                                    |
| Lifestyle        | 平日は仕事中心。休日は予定がなければ家で過ごしがち              |
| Digital Behavior | SNS、記事、友人の投稿などで気になる店・展示会・イベントを見かける     |
| Social Context   | 友人や気になる相手と出かけたい気持ちはあるが、自分から予定を作ることは少ない |
| Core Tension     | 本当は少し興味があるが、自分から動くほどではない               |

### 2.2 Background

Haruは、日常の中で「ちょっと気になる」ものをよく見つける。

SNSで流れてきた飲食店。
話題になっている展示会。
友人が行っていたイベント。
気になる相手と行けそうな店。
休日に行ったら面白そうな場所。

こうしたものに対して、Haruはまったく興味がないわけではない。
むしろ、「行ったら面白そう」と思うことはある。

しかし、その興味は強い目的にはならない。

絶対に行きたいわけではない。
今すぐ予約したいわけでもない。
誰かを誘ってまで行きたいかと言われると、少し面倒である。
自分から動くと、自分が行きたかったことになってしまう。

結果として、Haruの弱い興味は日常の中で流れていく。

### 2.3 Goals

Haruの目標は、強い意思を持って行動することではない。
むしろ、強い意思を持たなくても行動に移れる状態を作ることである。

* 本当は気になっていた場所に行く
* 休日を何となく消費せず、新しい体験を入れる
* 自分から強く望んだことにせず、行動する
* 失敗しても「自分の選択だった」と思いすぎない
* 誰かに「本当は行きたかったんだ」と思われすぎずに済ませる
* 行動のきっかけを外部に置く

### 2.4 Frustrations

Haruは、興味そのものがないわけではない。
行動化までの細かい負荷と、自分から始める心理的な重さに引っかかっている。

* 気になるものを見つけても、予定化する前に忘れる
* 店やイベントを探すのが面倒
* 相手を誘うメッセージを考えるのが面倒
* 日程を決めるのが面倒
* 自分から誘うと、行きたかった感が出てしまう
* 外れた時に、自分の選択だったことになるのが嫌
* 「行きたい」と明言するほどの熱量はない

### 2.5 Psychological Structure

Haruは、行動したくないわけではない。
ただ、自分から始めたくない。

Haruにとって必要なのは、完璧な提案ではない。
必要なのは、外部から押されたという構図である。

MyMomが勝手に聞いてきた。
MyMomが勝手に候補を出してきた。
MyMomが勝手に予定化相当のところまで話を進めた。
だから仕方なく行く。

この構図があれば、Haruは弱い興味を行動に変えやすくなる。

### 2.6 MyMom Fit

MyMomは、Haruに対して以下の価値を提供する。

* 自分から始めたわけではない状況を作る
* 弱い興味を拾って、行動に変える
* 店やイベントの候補を勝手に出す
* 日程や相手への連絡を詰める
* 予約・手配・予定化まで進んだように感じられる状態を作る
* 行動後に愚痴や感想を返せる

### 2.7 Success Moment

Haruにとっての成功体験は、行動そのものだけではない。
行動の理由をMyMomに置けることが重要である。

Haruが友人にこう言える状態が成功である。

> 「いや、別にめちゃくちゃ行きたかったわけじゃないんだけど、MyMomが勝手に進めてさ」
> 「予約されたなら行くしかないじゃん」
> 「まあ、行ったら行ったで面白かったけど」

### 2.8 Failure Moment

MyMomが単に便利な提案AIに見えた場合、Haruにとっての価値は弱くなる。

Haruが欲しいのは検索結果ではない。
Haruが欲しいのは、自分から始めたわけではないという構図である。

そのため、以下の状態になると失敗である。

* ユーザーから会話を始める必要がある
* 候補提示だけで終わる
* 予定化相当のところまで話が進まない
* MyMomが主導した履歴が残らない
* 「自分から始めたわけではない」と説明できない

## 3. Secondary Personas

## P2: 誘うきっかけを作れない人

### 3.1 Profile

| Item           | Description                      |
| -------------- | -------------------------------- |
| Name           | Ren                              |
| Age            | 24                               |
| Occupation     | 会社員                              |
| Lifestyle      | 仕事後や休日に人と会うことはあるが、自分から誘う頻度は高くない  |
| Social Context | 気になる相手や、久しぶりに会いたい友人がいる           |
| Core Tension   | 誘ってもいいが、自分から誘いたかったと思われるのが少し恥ずかしい |

### 3.2 Background

Renには、食事に誘ってみたい相手がいる。
ただし、強い確信があるわけではない。

食事くらいなら行ってもいい。
でも、自分から誘うのは少し重い。
店を探すのも面倒。
日程を聞くのも面倒。
相手に断られた時の気まずさもある。

そのため、Renは「また今度でいいか」と先延ばしにする。

Renに必要なのは、誘う意思を強くすることではない。
誘う理由を自分の外に置くことである。

### 3.3 Goals

* 気になる相手を自然に誘いたい
* 自分が前のめりに見えすぎないようにしたい
* 店選びや日程調整を軽く済ませたい
* 誘う理由を外部に置きたい
* 失敗した時に笑って流せる余地がほしい
* 相手に送る文面まで軽く用意してほしい

### 3.4 Frustrations

* 自分から誘うと気があるように見える
* 店選びでセンスを問われるのが嫌
* 相手に送る文面を考えるのが面倒
* 日程調整で会話が止まる
* 断られた時に自分の選択として残る
* 行く前から考えることが多い

### 3.5 Psychological Structure

Renは、相手と食事に行きたくないわけではない。
ただ、自分が誘いたかったことにしたくない。

MyMomが店を見つけてきた。
MyMomが予定を詰めてきた。
MyMomが相手に送る文面まで作った。
だから送った。

この構図があると、Renは誘う行動を取りやすくなる。

### 3.6 MyMom Fit

MyMomは、Renに対して以下の価値を提供する。

* 近況会話から気になる相手の存在を聞き出す
* 飲食店の候補を提示する
* 日程や場所を詰める
* 相手に送るメッセージを生成する
* 予約完了風の通知や予定化相当の結果を作る
* 「MyMomが勝手に進めた」と言える文脈を残す

### 3.7 Success Moment

Renが相手にメッセージを送れる状態。

> 「ここ予約されたっぽいから、よかったら行かない？」
> 「なんかMyMomがここでいいじゃんってうるさくて」

Renにとって重要なのは、誘う勇気が急に湧くことではない。
誘う理由が外から与えられることである。

### 3.8 Failure Moment

MyMomが「どこに行きたいですか？」と聞くだけなら、Renは動けない。
それでは結局、自分から始める必要があるからである。

## P3: 休日を流しがちな人

### 3.9 Profile

| Item         | Description                    |
| ------------ | ------------------------------ |
| Name         | Mio                            |
| Age          | 26                             |
| Occupation   | 会社員                            |
| Lifestyle    | 平日は忙しく、休日は予定がなければ家で休む          |
| Interest     | 展示会、映画、イベント、カフェなどに少し興味がある      |
| Core Tension | 何かした方がいい気はするが、自分から予定を入れるほどではない |

### 3.10 Background

Mioは、休日を有意義にしたい気持ちがある。
SNSやニュースで展示会やイベントを見かけると「ちょっと面白そう」と思う。

しかし、実際には予定化しない。

チケットを取るのが面倒。
日程を決めるのが面倒。
一人で行くか、誰かを誘うか考えるのも面倒。
そうしているうちに、イベント期間が終わる。

Mioは、毎回強く後悔するわけではない。
ただ、少しもったいなかったと思う。

### 3.11 Goals

* 休日に新しい体験を入れたい
* 気になっていた展示会やイベントに行きたい
* 自分で探し続けなくても候補が出てきてほしい
* 予定化まで進めてほしい
* 行って微妙でも、自分だけの選択として抱えたくない
* 外出のきっかけを外部に置きたい

### 3.12 Frustrations

* 気になるイベントを保存しても見返さない
* 開催期間が終わってから思い出す
* 一人で行くか誰かを誘うか決めるのが面倒
* 休日に予定を入れる決定力がない
* 自分から行きたかったと思われるのが少し恥ずかしい
* 候補だけ見ても行動に移らない

### 3.13 Psychological Structure

Mioは、外出したくないわけではない。
ただ、休日の予定を自分で作るほどのエネルギーがない。

MyMomが「これ面白そうじゃない？」と送ってくる。
MyMomが日程を聞いてくる。
MyMomがチケット手配や予定化に相当するところまで話を進める。
Mioは渋々それに乗る。

この構図があれば、Mioは休日に新しい体験を入れやすくなる。

### 3.14 MyMom Fit

MyMomは、Mioに対して以下の価値を提供する。

* 展示会やイベントの候補をPushする
* 開催期間や場所をもとに予定化を促す
* 候補日を聞き出す
* チケット手配相当の導線を作る
* カレンダー予定化する
* 行動後に感想や愚痴を返せる

### 3.15 Success Moment

Mioが休日に外出し、こう言える状態。

> 「なんかMyMomが勝手に予定入れてきたから行ってきた」
> 「別にそこまで行きたかったわけじゃないけど、まあ面白かった」

### 3.16 Failure Moment

候補だけ提示され、予定化まで進まない場合、Mioは動かない。
Mioに必要なのは情報ではなく、予定が進んでしまう感覚である。

| Name         | Sota                                 |
| Age          | 27                                   |

Sotaは、新しい店やイベントに興味がある。

店が微妙だったらどうしよう。

イベントが期待外れだったらどうしよう。
自分が選んだことになるのが嫌だ。

Sotaは、結果を自分だけで抱えたくない。

### 3.19 Goals

* 新しい体験に踏み出したい
* 外れた時に自分の判断ミスだと思いすぎたくない
* 結果に対して文句を言える相手がほしい
* 次回は少し改善されてほしい
* 失敗しても笑って流せる余地がほしい

### 3.20 Frustrations

* 自分で選んだ体験が外れると落ち込む
* 相手が楽しめなかった時に気まずい
* 店やイベント選びに自信がない
* 失敗を笑って流す理由がほしい
* 外れ体験を自分の選択として抱えるのが重い

Sotaにとって、MyMomは体験後の受け皿にもなる。

この構造によって、Sotaは新しい体験へのハードルを下げられる。

MyMomは、Sotaに対して以下の価値を提供する。

* 候補選びをMyMom主導にする
* 行動の起点をMyMom側に置く
* 結果に対する愚痴を受け取る
* フィードバックを次回の候補提示に活用する
* 外れ体験もMyMomとの関係性の一部にする

### 3.23 Success Moment

Sotaが体験後にこう言える状態。

> 「正直微妙だったけど、MyMomに文句言っといた」
> 「次はもうちょいマシなの出してもらう」

### 3.24 Failure Moment

MyMomが体験後のフィードバックを受け取れない場合、Sotaは結果を自分だけで抱えることになる。
それではMyMomを言い訳の対象にしづらい。

### FN-06: 体験後に文句を言いたい

このNeedsは、FR-08に接続する。

## 6. Excuse Triggers

## 6.1 Definition

Excuse Triggerとは、ユーザーが「自分から始めたわけではない」と説明できるきっかけである。

MyMomにおいては、以下のような体験要素がExcuse Triggerになる。

* MyMomから一方的に連絡が来る
* MyMomが弱い興味を聞き出す
* MyMomが候補を勝手に提示する
* MyMomが日程や相手を詰める
* MyMomが予約・手配・予定化まで進んだように感じられる状態を作る
* MyMom主導の履歴が残る
* MyMomへ愚痴や感想を返せる

## 6.2 Trigger 1: MyMom-Originated Contact

### Description

MyMomから会話が始まることで、ユーザーは自分から始めたわけではないと言える。

### Example

> 「MyMomがいきなり聞いてきたから」

### Related Requirements

* FR-01: MyMom起点のPush会話開始
* FR-02: ユーザー起点の自由会話制限

### User Story Direction

ユーザーとして、私は自分から会話を始めなくてもMyMomから連絡されたい。
なぜなら、自分から興味を示したことにしたくないからである。

## 6.3 Trigger 2: Weak Interest Extraction

### Description

ユーザーが明確に「行きたい」と言わなくても、MyMomが弱い興味を拾うことで、行動の入口が生まれる。

### Example

> 「ちょっと気になるって言っただけなのに、話が進んだ」

### Related Requirements

* FR-03: 弱い興味・未実行の関心の検知

### User Story Direction

ユーザーとして、私は曖昧な興味をMyMomに拾われたい。
なぜなら、強く行きたいと言わなくても行動のきっかけができるからである。

---

## 6.4 Trigger 3: Nudge Candidate

### Description

MyMomが勝手に候補を提示することで、ユーザーは自分で探したわけではないと言える。

### Example

> 「MyMomがこの店でいいじゃんって言ってきた」

### Related Requirements

* FR-04: お節介な候補提示

### User Story Direction

ユーザーとして、私はMyMomに候補を押されたい。
なぜなら、自分で選んだことにしなくても済むからである。

---

## 6.5 Trigger 4: Planning Pressure

### Description

MyMomが日程、場所、人数、相手への連絡などを詰めることで、ユーザーは予定化に巻き込まれる。

### Example

> 「いつ空いてるのって詰められて、気づいたら予定が決まってた」

### Related Requirements

* FR-05: 日程・場所・相手の聞き出し
* FR-06: 予約・手配・予定化の実行

### User Story Direction

ユーザーとして、私はMyMomに日程や相手への連絡まで詰められたい。
なぜなら、自分で予定を作ったという感覚を弱められるからである。

---

## 6.6 Trigger 5: Scheduled Result

### Description

予約完了風の通知、カレンダー予定、予約リクエスト、相手に送るメッセージなどが生成されることで、ユーザーは「行くしかない」と感じられる。

### Example

> 「もう予定っぽくなってるから行くしかない」

### Related Requirements

* FR-06: 予約・手配・予定化の実行
* NFR-05: MVP Feasibility

### User Story Direction

ユーザーとして、私は予定化相当の結果をMyMomに作られたい。
なぜなら、行動する理由を外部に置けるからである。

---

## 6.7 Trigger 6: Excuse Evidence

### Description

MyMom主導の会話履歴や通知が残ることで、ユーザーは他者に説明しやすくなる。

### Example

> 「ほら、MyMomが勝手に進めてるでしょ」

### Related Requirements

* FR-07: 言い訳として使える履歴・通知の生成
* NFR-03: Excuse Strength

### User Story Direction

ユーザーとして、私はMyMom主導で話が進んだ履歴を残したい。
なぜなら、他者に自分から始めたわけではないと説明できるからである。

---

## 6.8 Trigger 7: Complaint Loop

### Description

### Example

なぜなら、結果を自分だけの選択として抱え込まずに済むからである。

## 7. Anti-Personas

## 7.1 Anti-Persona Overview

MyMomは、すべてのユーザーに向いたサービスではない。
以下のようなユーザーは、MVPの主要対象ではない。

| Anti-Persona        | Why Not Target           |
| ------------------- | ------------------------ |
| 明確に目的を持って自分で動ける人    | MyMomによる外部のきっかけを必要としない   |
| 自由に相談できるAIを求める人     | MyMomはユーザー起点の自由会話を中心にしない |
| 完全な予約自動化だけを求める人     | MVPの価値は予約処理そのものではない      |
| 強い干渉を一切許容しない人       | MyMomのお節介体験と相性が悪い        |
| 危険・高額・重大な意思決定を任せたい人 | MVPでは日常的で低リスクな行動に限定する    |

---

## 7.2 Anti-Persona 1: 明確に目的を持って自分で動ける人

### Description

このユーザーは、行きたい場所ややりたいことが明確であり、自分で検索し、比較し、予約し、予定化できる。

### Why Not Target

MyMomの価値は、弱い興味を外部からのきっかけで行動化することにある。
すでに自分で行動できるユーザーにとって、MyMomのお節介は不要または邪魔に感じられる可能性がある。

### Design Implication

MyMomは、効率的な予約ツールとして設計しすぎない。
あくまで、自分から始めづらい人のための体験として設計する。

---

## 7.3 Anti-Persona 2: 自由に相談できるAIを求める人

### Description

このユーザーは、必要な時に自分から質問し、自由に会話し、AIに相談したい。

### Why Not Target

MyMomでは、会話の起点をMyMom側に置くことが重要である。
ユーザーから自由に会話を開始できると、「自分から始めたわけではない」という体験が弱くなる。

### Design Implication

MVPでは、自由相談よりもMyMomからのPushと返信体験を優先する。

---

## 7.4 Anti-Persona 3: 完全な予約自動化だけを求める人

### Description

このユーザーは、最短で予約を完了したい。
候補比較、空席確認、予約完了までを完全自動化したい。

### Why Not Target

MyMomのMVPでは、完全な外部予約API連携は必須ではない。
重要なのは、予約・手配・予定化まで進んだように感じられる状態と、言い訳として成立する文脈である。

### Design Implication

MVPでは、疑似予約、予約リクエスト生成、カレンダー予定化、予約完了風の通知、相手に送るメッセージ生成を有効な代替手段とする。

---

## 7.5 Anti-Persona 4: 強い干渉を一切許容しない人

### Description

このユーザーは、アプリからのPushやお節介な提案を嫌う。
自分のペースを邪魔されたくない。

### Why Not Target

MyMomは、お節介Push型の体験を前提にしている。
MyMomから一方的に連絡し、候補を提示し、予定化相当のところまで話を進めることがプロダクトの核である。

### Design Implication

MyMomは、このユーザーに合わせて完全に受け身のツールにはしない。
ただし、安全性と倫理境界として、明確な拒否は尊重する。

---

## 7.6 Anti-Persona 5: 危険・高額・重大な意思決定を任せたい人

### Description

このユーザーは、重大な意思決定や高リスクな行動もMyMomに進めてほしいと考える可能性がある。

### Why Not Target

MVPでは、飲食店、展示会、イベント、休日の外出など、日常的で低リスクな行動に対象を絞る。
危険・高額・健康被害・法的問題につながる行動は扱わない。

### Design Implication

Safety Boundaryを明確にし、MyMomのお節介が危険な強制に見えないようにする。

## 8.5 Final Persona Validation

MyMomのPrimary Personaは、明確な目的を持って自分で行動できる人ではない。
また、何もしたくない人でもない。

対象は、本当は少し気になっているが、自分から動くほどではない人である。

このユーザーは、行動のきっかけを自分の意思だけで作るのが苦手である。
しかし、MyMomが勝手に聞き、候補を出し、予定化相当のところまで話を進めることで、「自分から始めたわけではない」と言えるようになる。

その言い訳によって、ユーザーは行動しやすくなる。
一方で、その体験に慣れるほど、MyMomなしでは行動のきっかけを作りづらくなる未来像が生まれる。

この構造が、MyMomのUser Stories全体の前提である。
