# User Stories — MyMom

## 1. Purpose

このドキュメントは、MyMomのInceptionフェーズにおけるUser Story Creation成果物である。

目的は、`requirements.md`、`requirement-verification-questions.md`、`personas.md` で定義したプロダクト方針を、ユーザー心理と言い訳成立の構造に基づくUser Storiesへ展開することである。

MyMomの核は、ユーザーが本当は少し気になっているが、自分から動くほどではない行動に対して、**「自分から始めたわけではない」と言える状況**を作ることである。

MVPは「お節介Push・予約代行」である。
MyMomがユーザーに一方的に連絡し、弱い興味や予定を聞き出し、飲食店・展示会・イベントなどの候補を提案し、予約・手配・予定化まで進んだように感じられる体験を実演する。

このUser Storiesでは、単なる機能一覧ではなく、以下の心理構造を中心に扱う。

* 本当は少し気になっている
* でも自分から動くほどではない
* 自分が興味を持っていると認めるのが少し恥ずかしい
* 誘う、探す、予約する、予定化するのが面倒
* 誰かに押されたことにできれば動ける
* 失敗しても「自分の選択だった」と思いたくない
* MyMomを言い訳の対象にできると行動しやすい

## 3. Epic 1: MyMomから一方的に連絡される

### Epic Goal

ユーザーが自分から行動を始めたわけではない状態を作る。
MyMomから一方的に連絡が来ることで、ユーザーは自分の興味を自分から表明しなくても会話に巻き込まれる。

---

### Story ID

US-01

### Title

MyMomから会話が始まる

### User Story

ユーザーとして、私は自分から会話を始めなくてもMyMomから連絡されたい。
なぜなら、自分から興味を示したことにしたくないからである。

### Persona

* P1: 弱い興味を行動化できない20代社会人
* P3: 休日を流しがちな人

### Related Requirements

* FR-01: MyMom起点のPush会話開始
* FR-02: ユーザー起点の自由会話制限
* NFR-03: Excuse Strength

### Rationale

MyMomの体験では、会話の起点が重要である。
ユーザーから会話を始めると、「自分から頼んだ」構造になってしまう。

MyMomから連絡が来ることで、ユーザーは「自分から始めたわけではない」と言える。
この構図が、後続の候補提示、予定化、言い訳成立の土台になる。

### Acceptance Criteria

* MyMomからユーザーに通知が届く
* ユーザーが自分から新規会話を開始していない
* 通知文が機械的な連絡ではなく、母親的なお節介として表現されている
* ユーザーが通知に対して返信できる
* 会話履歴上、MyMomから会話が始まったことが確認できる

### Demo Notes

デモでは、ユーザーが何も操作していない状態からMyMomの通知が届く場面を見せる。
通知文は、たとえば以下のようにする。

> 「最近どうなの？休みの日ずっと家にいるんじゃないでしょうね」

この時点で、ユーザーが自分から相談したわけではないことが伝わる必要がある。

### Story ID

US-02

### Title

ユーザーから自由に会話を始められない

### User Story

ユーザーとして、私はMyMomに自由相談するのではなく、MyMomからの連絡に返信する形で会話したい。
なぜなら、自分から始めたことにしたくないからである。

### Persona

* P1: 弱い興味を行動化できない20代社会人
* P2: 誘うきっかけを作れない人

### Related Requirements

* FR-02: ユーザー起点の自由会話制限
* NFR-01: Simplicity
* NFR-03: Excuse Strength

### Rationale

MyMomは、ユーザーが自由に相談するための汎用チャットではない。
ユーザーから自由に会話を開始できると、行動の起点がユーザー側に戻る。

MyMomの価値は、ユーザーが受動的に巻き込まれることにある。
そのため、会話の開始主体はMyMom側に固定する。

### Acceptance Criteria

* ユーザーは任意のタイミングで新規会話を開始できない
* ユーザーができる操作は、MyMomからの連絡への返信を中心に制限されている
* UI上、自由入力欄が常に開放されていない
* 会話の起点がMyMom側であることが明確である
* ユーザーが「自分から頼んだ」と感じにくい

### Demo Notes

デモでは、ユーザー画面に自由相談の入口を出しすぎない。
MyMomから通知が来て、その通知に返信することで会話が始まる流れを見せる。

### Story ID

US-03

### Title

MyMomの連絡に渋々返信する

### User Story

ユーザーとして、私はMyMomからの連絡に渋々返信したい。
なぜなら、積極的に行動したのではなく、巻き込まれた感じを残したいからである。

### Persona

* P1: 弱い興味を行動化できない20代社会人
* P3: 休日を流しがちな人

### Related Requirements

* FR-01: MyMom起点のPush会話開始
* FR-02: ユーザー起点の自由会話制限
* NFR-02: Mother-like Tone

### Rationale

ユーザーが最初から前向きに返信すると、言い訳としての強度が弱くなる。
MyMomに対して「はいはい」「うるさいな」「別にいいけど」といった温度感で返信できることで、ユーザーは受動的に巻き込まれている感覚を持てる。

### Acceptance Criteria

* MyMomの初回通知に対して、ユーザーが短く曖昧に返信できる
* 返信内容が強い意思表示でなくても会話が続く
* MyMomがユーザーの渋い反応を受けても会話を止めない
* ユーザーの返信から「積極的に始めたわけではない」雰囲気が伝わる

### Demo Notes

デモでは、ユーザーの返信を以下のようにする。

> 「別に」
> 「まあ」
> 「うるさいな」
> 「知らん」

その反応に対してMyMomが会話を進めることで、巻き込まれ感を表現する。

## 4. Epic 2: 弱い興味を聞き出される

### Epic Goal

ユーザーが明確に「行きたい」「予約したい」と言う前の、弱い興味をMyMomが拾う。
曖昧な関心を行動の入口に変える。

---

### Story ID

US-04

### Title

曖昧な興味をMyMomに拾われる

### User Story

ユーザーとして、私は「ちょっと気になる」程度の曖昧な興味をMyMomに拾われたい。
なぜなら、強く行きたいと言わなくても行動のきっかけができるからである。

### Persona

* P1: 弱い興味を行動化できない20代社会人
* P3: 休日を流しがちな人

### Related Requirements

* FR-03: 弱い興味・未実行の関心の検知
* NFR-03: Excuse Strength

### Rationale

MyMomが対象にするのは、ユーザーが明確に行きたいと表明した行動ではない。
むしろ、ユーザーが「まあ」「気になるっちゃ気になる」「予定が合えば」程度に示す弱い興味である。

この曖昧さが残ることで、ユーザーは後から「自分が強く行きたかったわけではない」と言える。

### Acceptance Criteria

* ユーザーが強い意思表示をしなくても、MyMomが関心の兆候を拾う
* 「ちょっと気になる」「まあ行ってもいい」などの発話が検知される
* MyMomがその反応をもとに次の質問へ進む
* ユーザーが「強く希望したわけではない」と言える余地が残る

### Demo Notes

デモでは、ユーザーが以下のように曖昧に返す。

> 「まあ、気になるっちゃ気になる」
> 「別にめちゃくちゃ行きたいわけじゃないけど」
> 「予定が合えばね」

MyMomはこの弱い反応を拾い、候補提示へ進む。

### Title

面倒くささをMyMomに見抜かれる

### User Story

ユーザーとして、私は「面倒くさい」と言ってもMyMomに見抜かれたい。
なぜなら、本当は少し興味があるのに、面倒くささで流しているだけだからである。

* P2: 誘うきっかけを作れない人
* P3: 休日を流しがちな人

### Related Requirements

* FR-03: 弱い興味・未実行の関心の検知
* NFR-02: Mother-like Tone

### Rationale

ユーザーの「面倒くさい」は、必ずしも拒否ではない。
本当は少し興味があるが、探す、誘う、予約する、予定化する負荷を避けている場合がある。

MyMomは、この軽い回避を見抜き、お節介に会話を進める必要がある。

### Acceptance Criteria

* ユーザーが「面倒くさい」と言っても、MyMomが会話を完全には終了しない
* MyMomが「どうせ面倒くさがってるだけでしょ」といった母親的な返答をする
* 明確な拒否ではなく、軽い回避として扱える
* 次の候補提示や日程確認につなげられる

> 「行ってもいいけど面倒くさい」

MyMomはそれを受けて、候補を探す方向に進める。

## 5. Epic 3: お節介に候補を提示される

### Epic Goal

ユーザーが自分で候補を探す前に、MyMomが勝手に候補を提示する。
ユーザーが「自分で選んだわけではない」と言える状態を作る。

---

### Story ID

US-07

### Title

MyMomが勝手に候補を見つけてくる

### User Story

ユーザーとして、私はMyMomに勝手に候補を見つけてきてほしい。
なぜなら、自分で探したことにしたくないからである。

### Persona

* P1: 弱い興味を行動化できない20代社会人
* P3: 休日を流しがちな人

### Related Requirements

* FR-04: お節介な候補提示
* NFR-02: Mother-like Tone
* NFR-03: Excuse Strength

### Rationale

ユーザーが自分で候補を探すと、自分が行きたかったことになる。
MyMomが勝手に候補を出すことで、ユーザーは「自分で探したわけではない」と言える。

候補提示は、単なる検索結果ではなく、母親的なお節介として表現される必要がある。

### Acceptance Criteria

* 候補が飲食店、展示会、イベントなどMVP対象に沿っている
* 候補提示の文面が事務的ではなく、お節介として感じられる
* ユーザーが候補に対して曖昧に反応できる
* 候補提示が日程確認へつながる

### Demo Notes

デモでは、MyMomが以下のように候補を出す。

> 「ほら、こんなお店あるじゃない」
> 「ここでいいんじゃない？」
> 「あんたこういうの好きそうじゃない？」

候補を押しつけられるが、完全には嫌ではない

## 6. Epic 4: 日程・場所・相手を詰められる

### Epic Goal

MyMomが候補提示で止まらず、日程、場所、人数、相手への連絡など、行動に必要な情報を会話の中で聞き出す。
ユーザーが予定化に巻き込まれていく体験を作る。

---

### Story ID

US-10

### Title

MyMomに日程を詰められる

### User Story

ユーザーとして、私はMyMomに日程を詰められたい。
なぜなら、自分で予定を決めたのではなく、話が進んでしまったことにできるからである。

### Persona

* P1: 弱い興味を行動化できない20代社会人
* P3: 休日を流しがちな人

### Related Requirements

* FR-05: 日程・場所・相手の聞き出し
* FR-06: 予約・手配・予定化の実行
* NFR-03: Excuse Strength

### Rationale

候補提示だけでは、ユーザーは行動しない可能性が高い。
日程が決まることで、行動は一気に現実に近づく。

MyMomが日程を聞き出すことで、ユーザーは自分で予定を作ったのではなく、MyMomに詰められたと感じられる。

### Acceptance Criteria

* MyMomが候補提示後に日程を質問する
* ユーザーが曖昧に答えても、MyMomが補足質問を行う
* 日程候補が1つ以上確定する
* ユーザーが「気づいたら予定が進んでいた」と感じられる
* 会話履歴にMyMomが日程を詰めた流れが残る

### Demo Notes

デモでは、MyMomが以下のように聞く。

> 「で、いつ空いてるの？」
> 「来週の土日なら行けるでしょ？」
> 「予定空いてるなら入れちゃうよ」
