# ユーザーストーリー — MyMom

## エピック1: Slack断り代行（MVP）

### US-01: 断り代行を自動実行する
**ユーザーとして** 山田くん（断れない新卒エンジニア）は、  
**Slack DMで届いた出社・参加依頼をMyMomに自動で断ってほしい**。  
**なぜなら** 断る決断も、言葉を選ぶ苦労も、したくないから。

**受け入れ基準**:
- [ ] MyMomが60秒以内にSlack DM到着を検知する
- [ ] Bedrock Guardrailsが倫理チェックを通過してから送信される
- [ ] ユーザーのアクションなしに相手方へ断り文が送信される
- [ ] ユーザーへの通知は「断っておいたよ」のみ（実行前通知なし）

---

## エピック2: チャットUI + クイックリプライ

### US-03: ボタンを押すだけで会話が進む
**ユーザーとして** 山田くんは、  
**MyMomとのチャットで次の一言を考えなくていい**ようにしたい。  
**なぜなら** 質問を打つことすら面倒だから。

**受け入れ基準**:
- [ ] MyMomの返答ごとに、必ず2択のボタンが表示される
- [ ] ボタンをタップするだけで次のメッセージが送信される
- [ ] 2択はBedrockが文脈を読んで動的に生成する（固定テンプレートではない）
- [ ] 自由入力も常に可能（ボタンと並列）

---

## エピック3: パーソナリティ分析・プロファイル公開

### US-04: パーソナリティカードを見て、Twitterに晒す
**ユーザーとして** 山田くん（1週間使用後）は、  
**MyMomが分析した自分の性格カードを見て友達に見せたい**。  
**なぜなら** 「AIに分析されたら面白いことになった」という体験を共有したいから。

**受け入れ基準**:
- [ ] 1週間の使用後に初回カードが生成される
- [ ] 断り苦手度・先延ばし傾向・完璧主義度・承認欲求度の4スコアが表示される
- [ ] 公開はオプトイン制（デフォルトは非公開）

### US-05: MyMomが自分のことをどんどん理解してくれる
**ユーザーとして** 山田くんは、  
**MyMomの返答が使えば使うほど自分に合ったものになってほしい**。  
**なぜなら** 「お母さん」なら自分のことを知っているはずだから。

**受け入れ基準**:
- [ ] パーソナリティプロファイルが毎回のBedrock呼び出しのsystem promptに注入される
- [ ] プロファイルは週次で更新される
- [ ] ユーザーが「最近変わった気がする」と感じる変化がある

## エピック4: 責任SLA

### US-06: MyMomが失敗したら、MyMomが謝る
**ユーザーとして** 山田くんは、  
**MyMomのミスでトラブルになっても、自分は何もしたくない**。  
**なぜなら** 失敗の精神的コストをゼロにすることがMyMomの本約束だから。

**受け入れ基準**:
- [ ] MyMomが失敗を自動検知する
- [ ] BedrockがMyMomのキャラクターで謝罪文を生成し、相手方に送信する
- [ ] リカバリアクションが自律実行される
- [ ] ユーザーへは「対処しておいたよ」通知のみ（詳細は要求なし）

## エピック5: Slackでお母さんと会話（MVP追加）

### US-08: SlackでそのままMyMomと話せる
**ユーザーとして** 山田くんは、  
**MyMomのSlack DMチャンネルで直接お母さんと会話したい**。  
**なぜなら** 別のアプリを開かずに、Slackを使いながらいつでもお母さんに相談できるから。

**受け入れ基準**:
- [ ] MyMomのSlack DM（`@MyMom`）にメッセージを送ると、Bedrock Agentが返答する
- [ ] 「お母さん考えてるよ…ちょっと待ってね🤔」が先行表示される（3秒以内）
- [ ] Bedrock Agentのセッション（`chat-{userId}`）で会話履歴が継続される
- [ ] Slack署名検証（HMAC-SHA256）が常時実施される
- [ ] Slackのリトライリクエスト（`x-slack-retry-num`）を重複排除する

## エピック6: おせっかいプッシュ型通知（将来機能）

### US-09: お母さんが先回りして気遣ってくれる
**ユーザーとして** 山田くんは、  
**自分が何もしなくてもMyMomが日常の気遣いをプッシュしてきてほしい**。  
**なぜなら** 本物のお母さんは「何もしないから動く」のではなく「おせっかいで動く」から。

**受け入れ基準**:
- [ ] 「最近気になってる人いる？」などのおせっかいプッシュがSlack DMに届く
- [ ] ユーザーが「いる」と答えたら3日後にそっとDMを送っておく
- [ ] 「ちょっと部屋が散らかってない？」など日常の気遣い通知が週次で届く
- [ ] 依存度スコア80超・14日継続でセルフケア通知に切り替わる（ブレーカー）

### US-11: 気になる人へのアポをお母さんが勝手に取っておく
**ユーザーとして** 山田くんは、  
**気になる人に連絡するタイミングも言葉も考えたくない**。  
**なぜなら** 「どう声をかけるか」を考えている間に機会は消えるから。

**シナリオ**:

```
（ある水曜の夜、山田くんは何もしていない）

MyMom → 山田くん DM:
「ねえ、最近気になる人でもできたの？なんかそういう雰囲気あるよ」

山田くん:
「いるっちゃいるんだけど、どう声かけたらいいかわかんなくて」

MyMom:
「じゃあお母さんに任せて。その人のこと少し教えて」

山田くん:
「同じチームの田中さん。コーヒー好きそう」

MyMom:
「わかった。あとは何もしなくていいよ」

---

（3日後、木曜の朝）

田中さん → 山田くん DM:
「山田くん、ランチのお誘いありがとうございます！木曜の12:30、いいですよ！」

山田くん: 「？？？」

MyMom → 山田くん DM:
「ランチのアポ取っておいたよ。木曜12:30、駅前のカフェ。
 あなたがコーヒー好きって伝えたら、田中さんも好きだって。よかったね。」
```

**受け入れ基準**:
- [ ] MyMomがユーザーの行動パターン・感情的なシグナルからプッシュのタイミングを判断する
- [ ] ユーザーが相手の名前と文脈を伝えると、MyMomが自然な誘い文を生成して送信する
- [ ] 送信前に「あとは何もしなくていいよ」とだけ伝える（確認画面なし、信頼度80%以上の場合）
- [ ] 相手が承諾したらMyMomがユーザーに日時・場所を通知する
- [ ] 断られた場合もMyMomが受け取り、「今回はタイミングじゃなかっただけ」と慰める

## エピック7: ライフイベント対応（将来機能）

### US-10: 転職したらMyMomもアップデートされる
**ユーザーとして** 山田くん（転職決定後）は、  
**MyMomに「転職版お母さん」として入社手続きを全部やってほしい**。  
**なぜなら** 書類手続きや保険切り替えを考えたくないから。

**受け入れ基準**:
- [ ] メール・カレンダーからライフイベントを自動検知する
- [ ] 「転職版お母さん」へのバージョンアップを提案する
- [ ] 入社手続き・保険切り替え・住民票変更等をリスト化して順番に実行する
